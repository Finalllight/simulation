# 无头物理仿真数据生成系统 — 组会汇报稿

---

## 一、课题背景与目标

本次工作的目标是构建一个**无头物理仿真数据生成系统**。所谓"无头"，是指物理引擎只做数值计算，不进行任何画面渲染。系统的输入是设备的 CAD 三维模型和运动参数，输出是设备在操作指令驱动下的运动学数据（位置、速度、加速度的时间序列）。

这个系统的应用场景包括：替代昂贵的实物实验进行前期验证、为数字孪生系统提供训练数据、以及在设备尚未制造完成时进行控制算法的预研。

本阶段的核心任务是：完成系统架构设计与首个设备类型的建模仿真，验证技术路线的可行性。

---

## 二、系统架构设计

系统采用四层模块化架构，各层职责明确、松耦合，便于后续扩展新的设备类型：

**第一层：模型构建层（Model Layer）**
将 CAD 模型（STEP/STL 格式）和运动参数（YAML 格式）解析后，构建为 MuJoCo 物理引擎可读取的 MJCF 场景描述文件。每个设备类型实现统一的 `DeviceModel` 抽象接口，新增设备只需实现该接口即可接入系统。

**第二层：指令解释层（Command Layer）**
接收高层操作指令（如"前进一格"、"升高 0.2 米"），将其翻译为物理引擎的执行器控制信号。同时负责网格占位管理、边界校验、编组展开等功能。

**第三层：仿真执行层（Engine Layer）**
基于 MuJoCo 物理引擎的无头模式运行。MuJoCo 是目前开源领域最快的刚体动力学引擎，由 Google DeepMind 维护，被广泛用于机器人学研究。我们选择它的核心理由是：物理计算与渲染完全解耦，天然支持无头运行，并且 Python 绑定成熟。

**第四层：数据输出层（Output Layer）**
在每个仿真步长采集所有被追踪物体的位置、速度、加速度，组织为时间序列数据结构，支持导出为 CSV 和 NumPy 格式。

### 技术选型

| 项目 | 选择 | 理由 |
|------|------|------|
| 物理引擎 | MuJoCo 3.x | 开源最快，天然 headless，Python 生态好 |
| 语言 | Python 3.10+ | 开发效率高，科学计算生态完善 |
| CAD 解析 | trimesh + pythonocc-core | 支持 STL/STEP 双格式，可提取质量/惯量 |
| 执行器控制 | Position Servo (PD) | 自动产生加速→匀速→减速的物理合理剖面 |

## 三、首个设备建模：网格轨道四轮转运小车

### 3.1 设备描述

该设备运行于由横纵轨道组成的网格平面上。小车可在网格上沿 X 或 Y 方向移动，具备 Z 轴升降平台用于货物装卸。多个小车可编为一组协同运输大型货物，同组车辆保持相同的速度和高度。

### 3.2 MuJoCo 物理模型

每辆小车在 MuJoCo 中建模为包含 3 个主动自由度的刚体系统：

- **X 轴滑动关节（slide joint）**：沿网格 X 方向平移，对应左右移动
- **Y 轴滑动关节**：沿网格 Y 方向平移，对应前后移动
- **Z 轴滑动关节**：垂直方向升降，位于子 body "lift"上，范围 [0, 0.4m]

每个主动自由度配备一个 Position Actuator（位置伺服），使用 PD 控制律：

```
F = kp · (target − qpos) − kv · qvel
```

通过调节 kp/kv 增益，使系统呈现临界阻尼响应，自动产生加速→匀速→减速的运动剖面，无需手动规划轨迹。增益值根据车辆质量自动计算：

| 方向 | kp | kv | 对应响应 |
|------|-----|-----|---------|
| X/Y 平移 | 1000 | 600 | 120 kg 质量，fn ≈ 0.5 Hz |
| Z 升降 | 20000 | 900 | 10 kg 平台质量，重力补偿 |

车辆底盘使用 MJCF 基元几何体（box）建模，车轮使用静态 cylinder 几何体（在当前阶段不参与接触计算）。若提供 CAD 模型（STL/STEP），可通过管线自动提取外形尺寸和质量属性。

### 3.3 指令集

系统当前支持的指令词汇表：

| 指令 | 目标 | 效果 |
|------|------|------|
| MOVE_FORWARD | vehicle/group | 沿 +Y 移动一个网格单元 |
| MOVE_BACKWARD | vehicle/group | 沿 -Y 移动一个网格单元 |
| MOVE_LEFT | vehicle/group | 沿 -X 移动一个网格单元 |
| MOVE_RIGHT | vehicle/group | 沿 +X 移动一个网格单元 |
| LIFT_UP | vehicle/group | 升高指定高度（默认 0.05m） |
| LIFT_DOWN | vehicle/group | 降低指定高度 |
| STOP | vehicle/group | 紧急停止，保持当前位置 |
| FORM_GROUP | 多个 vehicle | 将多辆车编为一组 |
| DISSOLVE_GROUP | group | 解散编组 |
| MOVE_TO_CELL | vehicle/group | 移动到指定网格坐标 |

### 3.4 编组机制

编组采用**逻辑同步**而非物理约束。当指令目标为一个组时，解释器会将该指令展开到组内所有成员，同时为所有成员设置相同的执行器目标，然后同步步进直到所有车辆到位。任何成员的移动路径越界或被占用，整组操作将被拒绝。逻辑编组相比物理约束（如 MuJoCo weld constraint）的优势在于：可在任意时刻动态组队和解散，没有约束求解器的收敛问题，且每辆车仍然保留独立的物理状态。

## 四、关键技术问题与解决方案

### 4.1 Z 轴重力补偿

升降平台质量为 10 kg，在重力作用下（g = 9.81 m/s²）受到约 98 N 的向下恒力。标准的 PD 位置伺服在恒力扰动下会产生稳态误差：

```
ess = mg / kp
```

当 kp = 2000 时，稳态误差约为 0.049 m，超出了 0.02 m 的允许误差范围。解决方案是将 Z 轴 kp 提升至 20000，使稳态误差降至 0.005 m 以内；同时将 kv 从 2000 降至 900，使系统保持临界阻尼（ζ ≈ 1.0）以避免振荡。

### 4.2 嵌套体数值刚度

初始设计中，四个车轮被建模为 lift body 下的子 body，每个带有被动铰链关节。这导致 MuJoCo 的 Featherstone 铰接体算法在 Z 轴方向的等效惯量急剧增大，Z 轴位置伺服收敛速度下降了约 20 倍（从 200 步收敛变为 5000 步仍不收敛）。解决方案是将车轮改为 lift body 上的静态几何体，不参与动力学计算。车轮旋转数据可通过车辆 XY 速度间接推得。此改动使 Z 轴响应时间从 25 秒以上降至约 0.2 秒（模拟时间）。

### 4.3 执行器初始化

MuJoCo 的位置执行器默认控制目标（ctrl）为 0。若车辆的初始关节位置不为 0（例如初始在网格 (2, 0) 位置，关节 qpos 为 2.5 m），则仿真一启动，执行器就会将车辆拉向原点。解决方案是在设置初始关节位置后，立即将执行器控制目标设为与当前关节位置一致，使车辆稳定在初始位置，直到收到移动指令。

## 五、验证结果

基于 10×10 网格、两辆转运小车的测试场景，进行了完整的功能验证：

### 5.1 功能测试

| 测试项 | 预期结果 | 实际结果 | 状态 |
|--------|---------|---------|------|
| 单步前进移动 | 移动一个网格单元 | (0,0) → (0,1)，位移 1.0m | 通过 |
| 连续多步移动 | 连续移动并准确定位 | 3 次前进 + 3 次右移，每步准确 | 通过 |
| Z 轴升降 | 上升 0.3m | 稳态值 0.295m，误差 < 5mm | 通过 |
| Z 轴下降 | 下降 0.2m | 稳态值 0.098m，误差 < 2mm | 通过 |
| 编组形成 | 两车组队 | 成功，偏移量记录正确 | 通过 |
| 编组移动 | 两车同步移动 | 两车同时到位，相对位置不变 | 通过 |
| 编组解散 | 恢复独立控制 | 后续单步指令正确执行 | 通过 |
| 越界保护 | 指令被拒绝 | 移出网格时返回错误 | 通过 |
| 碰撞保护 | 目标格有车时拒绝 | 占位检测正确 | 通过 |

### 5.2 运动学数据质量

从仿真生成的时间序列数据中提取的关键指标：

- **速度上限**：1.17 m/s（参数设定上限 1.2 m/s，未超限）
- **加速度剖面**：呈现明显的三段式特征——加速度上升段 → 匀速巡航段 → 减速度下降段
- **编组同步精度**：两车相对距离在编组前后保持一致（偏差 < 2 cm）
- **数据采样率**：200 Hz（仿真时间步长 0.005s），每条命令可产生 200-400 个数据点

### 5.3 实时性

在软实时要求（< 1 秒）下，每条指令的平均执行时间为：

| 操作类型 | 仿真步数 | 模拟时间 | 实际耗时 |
|---------|---------|---------|---------|
| 单步平移 | ~300 步 | 1.5 s | < 0.3 s |
| 升降操作 | ~200 步 | 1.0 s | < 0.2 s |
| 编组移动 | ~400 步 | 2.0 s | < 0.4 s |

实际耗时远小于 1 秒的软实时要求，且模拟时间可通过调大 dt 进一步加速。

## 六、后续工作计划

1. **CAD 模型接入**：完成 STL/STEP 管线联调，用真实设备的三维模型替换基元几何体
2. **参数标定**：以实物设备运行数据为基准，标定仿真模型的物理参数（摩擦系数、执行器响应特性）
3. **新设备扩展**：基于 `DeviceModel` 抽象接口，接入第二种设备类型（如六轴机械臂或无人机）
4. **数据管线完善**：增加批量指令序列执行模式和 HDF5 等高效数据格式导出
5. **精度验证**：将仿真输出与真实设备传感器数据进行定量对比，评估模型保真度

## 七、总结

本阶段完成了无头物理仿真数据生成系统的架构设计与核心实现。系统以 MuJoCo 为物理引擎底座，采用模块化四层架构，已成功支持网格轨道转运小车的完整仿真——包括 XY 平移、Z 轴升降、多车编组等全部功能。生成的仿真数据呈现合理的物理特征（三段式速度剖面、重力补偿稳态误差可控），满足软实时性能要求，架构具备良好的扩展性以支持后续更多设备类型的接入。
